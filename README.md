# Project Manager

> [!IMPORTANT]
> **Project Status: Archived / Legacy** <br />
> This project is archived and no longer maintained. I built this during my first year of web development to experiment with advanced JavaScript concepts and backend routing. While unfinished, it marks a major milestone in my growth as a developer.

---

## Technical Highlights

Despite the unpolished exterior, this project served as an excellent playground for mastering core software engineering principles in vanilla JavaScript:

* **Custom Event Emitters:** Implemented from scratch to handle decoupled, event-driven communication between independent modules.
* **OOP Architecture:** Structured the core application using JavaScript classes to cleanly manage application state and business logic.
* **Backend Integration:** Built a custom server environment to handle basic data persistence and routing.

---

## Retrospective and Lessons Learned

While I originally intended to complete this tool, I chose to leave it unfinished. Spending time polishing the visual layer of this legacy codebase offered a lower learning return than pivoting to newer, more modern stacks. 

Looking back, this project taught me several critical lessons about software development:

### 1. Feature Creep and Scope Control

> [!WARNING]
> **Takeaway:** Always establish a Minimum Viable Product (MVP) first.
> I constantly tried to add advanced features before the foundational ones were fully stabilized. Attempting to manage a massive scope as a solo developer taught me the absolute necessity of strict scope control.

### 2. Architectural Scalability

> [!NOTE]
> **Takeaway:** Early design choices heavily dictate future technical debt.
> Although the code was designed to be modular, a few early architectural mistakes caused complexity to spiral as the project scaled. This was a fantastic, hands-on lesson in structural planning.

### 3. Prioritizing Logic Over UI

Because my primary focus was mastering backend integration and complex JavaScript logic, the user interface was intentionally left minimal and unpolished. 

### 4. Outgrowing the Codebase

My development skills quickly outgrew the architecture of this repository. Instead of spending weeks heavily refactoring vanilla JavaScript to fix structural issues, I made the conscious decision to freeze this project and apply my new knowledge to modern tools like React and Express in future repositories.
